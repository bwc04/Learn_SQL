Course step #6: Joins

The JOIN clause allows data across multiple tables to be combined. Typically the JOIN
is followed by conditionals that allow us to find and match the correct information between the tables.

Say we have 2 tables:

Table 1: pets
schema: id, name, species

Table 2: pet_owners
schema: id, name, pet_id 

The information regarding pets and their owners in this case are in seperate tables. if we wanted to connect
each pet to it correct owner, we could use JOIN to find each pets corresponding owner. The conditional we would
use in this case would be to match the pets id to the pet_owners pet_id.

    SELECT p.name AS pet_name, po.name AS owner_name
    FROM pets AS p INNER JOIN pet_owners AS po
    ON p.id = po.pet_id;

The ON clause allows us to determine which columns from each table to use to combine the tables. The renaming is optional
however in cases where both tables have similar column names, you have to differentiate between them using pet.id and pet_owner.id

There are multiple types of JOINS:
    1. INNER JOIN: The resulting rows must have it corresponding value appear in both tables. If a id exists in one table
       but not the other, it will not appear.
    2. OUTER JOINS (LEFT, RIGHT): Outer joins will include all rows from either the LEFT or RIGHT table as you specified, and
       any matching rows from the other table. Any unmatched columns from the other table will have it value appear as NULL 
    3. FULL JOIN: All rows from both tables. Any unmatch rows will have it value set to NULL.

* Typically we will only really use INNER JOIN and LEFT/RIGHT JOINS
